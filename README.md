## 주제를 정한 이유

정신질환은 한 번의 진료로 끝나기보다 꾸준히 병원을 방문하고 약을 복용해야 하는 경우가 많습니다. 저희 팀은 이 과정에서 환자가 실제로 어느 정도의 비용을 부담하는지, 정신질환이 없는 환자와 비교했을 때 차이가 있는지 궁금했습니다.

처음에는 연령, 질환 종류, 치료 방법 등 여러 방향을 함께 살펴봤습니다. 분석을 진행하면서 정신질환 환자의 진료비와 투약료 차이가 눈에 띄었고, 최종적으로는 **비용 부담을 줄이면서 치료를 꾸준히 이어갈 방법**을 정책으로 제안했습니다.

## 사용한 데이터

HIRA 교육에서 제공한 비식별 데이터를 사용했습니다.

| 데이터 | 사용한 내용 |
|---|---|
| `EDU200` | 환자 및 진료 건 정보, 진료비, 본인부담금 |
| `EDU400` | 주상병·부상병 코드 |
| `EDU300` | 병원에서 발생한 투약 상세 |
| `EDU530` | 약국에서 발생한 투약 상세 |

`EDU200`과 `EDU400`을 환자·진료 건 기준으로 합친 뒤, 상병코드에 정신질환 코드가 있는 환자와 그렇지 않은 환자를 나눴습니다. 암, 파킨슨질환, 크론병, 치료재료대처럼 비용 차이가 큰 항목은 비교에서 제외했습니다.

```mermaid
flowchart LR
    A[진료 내역 EDU200] --> C[진료 건별 상병 결합]
    B[상병 내역 EDU400] --> C
    C --> D[고비용 질환·치료재료 제외]
    D --> E[정신질환군 / 비교군 분리]
    E --> F[진료비 비교]
    E --> G[병원 EDU300 / 약국 EDU530 투약료 비교]
    F --> H[정책 제안]
    G --> H
```

가공 파일과 변수에 대한 설명은 [data/README.md](data/README.md)에 정리했습니다.

## 다시 확인한 분석 결과

포트폴리오를 만들면서 남아 있는 CSV를 다시 집계했습니다. 발표 당시에는 짧은 기간 안에 여러 분석을 동시에 진행해서 계산 과정과 설명이 충분히 정리되지 못한 부분이 있었습니다. 아래 수치는 현재 보관 중인 최종 CSV를 `scripts/summarize_claims.py`로 다시 계산한 값입니다.

### 진료 건당 본인부담금

| 지표 | 비교군 | 정신질환군 | 차이 |
|---|---:|---:|---:|
| 분석 레코드 수 | 132,888 | 8,103 | - |
| 건당 평균 요양급여비용총액 | 51,168원 | 61,694원 | +20.6% |
| 건당 평균 본인부담금 | 17,753원 | 21,018원 | **+18.4%** |

정신질환군의 건당 평균 본인부담금은 비교군보다 약 3,264원 높았습니다.

### 환자 1인당 투약료

| 구분 | 비교군 | 정신질환군 | 배수 |
|---|---:|---:|---:|
| 병원 | 9,889원 | 22,125원 | **2.24배** |
| 약국 | 7,715원 | 17,896원 | **2.32배** |

비교군의 환자 수가 많아서 전체 투약료 합계는 비교군이 더 컸습니다. 하지만 환자 한 명을 기준으로 보면 병원과 약국 모두 정신질환군의 투약료가 2배 이상 높았습니다.

여기서 투약료는 상세 진료내역의 `AMT`를 환자별로 합한 값입니다. 환자가 직접 낸 본인부담금과 같은 뜻은 아닙니다.

### 발표에서 함께 다룬 내용

발표에서는 비용 외에도 연령대, 정신질환 종류, 치료 방법을 분석했습니다.

- 고령층에서 정신질환 환자 비율이 높아지는 경향
- 정신 및 행동장애, 불면증, 우울증, 공황장애가 많이 나타난 점
- 작업·오락요법과 집단정신치료를 받은 환자의 방문 횟수 차이
- 주요 정신질환 사이의 연관규칙

이 분석들은 당시 발표자료에는 남아 있지만 원 계산 코드는 보관하지 못했습니다. 그래서 README의 대표 수치에는 다시 계산할 수 있는 진료비·투약료 결과만 사용했습니다. 자세한 구분은 [분석 과정](docs/methodology.md)에 적었습니다.

## 제안한 정책

### Win-Win Wellness

진료와 복약을 꾸준히 이어간 환자의 진료비·약제비 부담을 줄여주는 아이디어입니다. 단순히 지원금을 지급하는 것보다 치료 참여와 지원을 연결하면 치료 중단을 줄일 수 있지 않을까 생각했습니다.

### Stay Well, Stay Real

고령층을 대상으로 집단정신치료, 작업·오락요법, 가벼운 운동과 야외 활동을 함께 제공하는 아이디어입니다. 분석 중 고령층의 정신질환 비율과 비약물 치료 방법에 주목하면서 제안했습니다.

두 제안의 발표 당시 내용과 보완할 점은 [정책 제안 문서](docs/policy-proposals.md)에 정리했습니다.

## 아쉬웠던 점

대회 기간이 짧아 전처리 기준과 분석 코드를 체계적으로 남기지 못했습니다. 특히 발표에서 사용한 연령대·치료 유형 분석은 결과 이미지만 남아 있어 지금 완전히 재현하기 어렵습니다.

또한 정신질환군과 비교군의 연령, 성별, 동반질환 차이를 통계적으로 보정하지 않았습니다. 따라서 이 결과는 두 그룹의 차이를 살펴본 탐색적 분석이며, 정신질환이 비용 차이의 직접적인 원인이라고 해석할 수는 없습니다.

이번에 포트폴리오를 정리하면서 남아 있는 데이터로 비용 지표를 다시 계산하고, 재현 가능한 부분과 그렇지 않은 부분을 구분해 기록했습니다.

## 부록: SQL 재구현

### 왜 SQL로 재구현했는지

원 분석은 Python/Pandas로 수행했고, 포트폴리오를 정리하면서 같은 데이터를 DuckDB로 다시 구현했습니다. 명세서·환자·상병·투약의 키와 집계 단위를 명시적으로 다루면서 조인 전에 집계 단위를 맞추는 과정을 드러내려 했습니다.

### 1:N 조인과 중복 합산

EDU200은 명세서당 한 행, EDU400은 명세서당 여러 상병 행입니다. 두 테이블을 그대로 조인한 뒤 금액을 SUM하면 한 명세서의 비용이 상병 수만큼 반복됩니다. 실행 결과 총액은 비교군에서 3.86배, 정신질환군에서 6.35배로 부풀었습니다.

집단별 배수가 다른 이유도 데이터에서 확인됩니다. 명세서당 상병 행 수는 정신질환 명세서가 평균 5.87행, 비교군이 3.29행입니다. 정신질환 명세서에 동반질환 코드가 더 많이 기재되기 때문에 같은 조인 실수를 해도 정신질환군 쪽이 더 크게 부풀어 오릅니다.

### 집계 단위에 따라 달라지는 결론

명세서 단위로 코호트를 나누면 한 환자가 정신질환 명세서와 일반 명세서를 모두 가질 수 있어 두 집단이 겹칩니다. 실제로 명세서 단위 비교에서는 비교군 환자 수가 1,553명으로 전체 환자 수와 같았습니다.

환자 단위로 다시 나누면 정신질환 이력 환자는 525명, 없는 환자는 1,028명입니다. 이 기준에서는 정신질환군의 환자당 투약비가 병원 2.05배, 약국 1.69배 높게 나타났으며, 원 분석의 2.24배·2.32배와 방향이 일치합니다.

원 분석은 이미 가공된 산출물을 기준으로 계산했고, 이번 SQL은 원천 테이블에서 약품 항목만 필터링해 다시 집계했습니다. 필터 기준이 달라 절대 금액은 직접 비교할 수 없으며, 집단 간 배수만 비교했습니다.

따라서 같은 데이터에서도 집계 단위에 따라 결론이 달라집니다. 명세서 단위로 보면 정신질환군 투약비가 낮게, 환자 단위로 보면 높게 나옵니다.

### 검증

조인 전후 행 수와 키 개수 대조, 키 중복·결측 확인, 참조 무결성, 금액 총계 보존을 SQL로 검증했고 모두 통과했습니다. 원본 총액 = 코호트 총액 + 제외 명세서 총액 등식도 확인했습니다.

### 실행 방법

```bash
pip install duckdb
python scripts/convert_encoding.py --data-root /path/to/csv
python scripts/run_sql.py --data-root /path/to/csv
```

원본 CSV는 cp949이므로 UTF-8로 변환한 뒤 적재합니다. 두 스크립트 모두 변환 폴더가 아니라 원본 CSV 폴더를 `--data-root`로 지정합니다.

### 원 Pandas 분석과의 관계

원 프로젝트 코드를 옮기거나 결과를 재현한 작업이 아닙니다. 비교군 제외에 사용한 정확한 코드 목록이 남아 있지 않아, `sql/03_mental_cohort.sql`에 이번 재구현에서 사용한 목록을 명시했습니다. 따라서 결과는 원 분석과 정확히 같지 않을 수 있습니다.

### SQL 파일 구성

- `sql/01_schema.sql`: 4개 테이블의 DuckDB 스키마와 키·카디널리티를 정의합니다.
- `sql/02_load.sql`: UTF-8로 변환된 CSV를 테이블에 적재합니다.
- `sql/03_mental_cohort.sql`: 정신질환 코호트와 비교군을 명세서 단위로 정의합니다.
- `sql/04_cost_analysis.sql`: 1:N 조인에서 발생하는 중복 합산과 사전 집계 후 결과를 비교합니다.
- `sql/05_medication.sql`: 병원과 약국 투약비를 명세서 및 환자 단위로 집계합니다.
- `sql/06_validation.sql`: 행 수, 키, 참조 무결성, 금액 보존을 검증합니다.

python scripts/summarize_claims.py --data-root ..
